# 0141 — Scanner Samples tab: Zoom session dragged onto draft clip slots, exported MP3 320 (+ optional WAV) with tags and label cover; three columns shared with Scans

`2026-11-23` · proposed · Figma: BACKEND → `Scanner`: section `samples · components` (`waveform` size small | large, `session clip` state default | playing | assigned | dragging, `clip slot` state filled | target | empty, `clip preview` state default | trimmed, `media status` kind images | clips × state some | none, `draft row` state default | hover | selected, `scanner tabs` mode scans | samples, `session head` with Clear, `export panel`); icons `icon/icon-image`, `icon/icon-waveform` (page icons); screens "Scanner v3 - samples, assigning / samples, no session yet / scans, same drafts column"; frame "notes · v3 samples tab, shared drafts column"

**Context.** Gio records the clips from his mixer onto a Zoom H4's SD card: Rec/Stop per side, records changed in between, while doing something else, with no Mac by the mixer. The Zoom often loses its clock, so the files have meaningless names and dates; renaming them by listening is the slow part. He rejected recording into the Mac and matching by draft order. He asked (2026-11-23) for a second tab in the Scanner app where the session's files are dragged into the draft's slots and renamed by the app, exported to chosen local folders as WAV (he may DJ with them) and MP3 320 with ID3 tags and the label of that side as cover and normalize to 0 dB (then parked, see Export); trimming silence only as an optional action; an in-app player. He feared that renaming on the SD card loses a wrongly dragged file. Then: the left column is the same for scans and samples, it lists every draft (search filters it) and each row shows small icons for images and samples already there.
**Decision.**
- **Three columns, same in both tabs** (Gio 2026-11-23 08:33, replacing a first version where the draft opened inside the list). **Left** = pick the SKU: every draft (`scan-targets` returns up to 500), the search field filters it; a `draft row` shows `media status`: image icon + number of scans, waveform icon + number of clips, only the count (no total); at least one = green chip (new semantic `surface/success` → acid-green, `text/on-success` → black, 15.6:1), none = red chip (`surface/alert` + `text/on-alert`, backend white on red 4.8:1); the number keeps it readable without colour. **Center** = the work, switched by `scanner tabs`: the scanner preview, or the session list + player. **Right** = the selected draft: `draft head`, its slots (Images of 0138, or Clips: one `clip slot` per Discogs position, names from `scan-targets`), then the scan settings or the `export panel`.
- **Session.** The Zoom folder (or files) is dropped on the center or picked with Import…, and **copied** to a local session folder with the original names. The SD card is never written. Each `session clip` keeps its original name; assigning it to a slot only maps it (`STE-014 → 48213_b1_…`), visible on both sides, reversible (x, drop elsewhere, Cmd+Z). A clip fills one slot at most. **Remove / Clear** (Gio 2026-11-23): an x on each `session clip` takes it out of the list (its local copy goes to the Trash, the SD card is untouched; an assigned clip also leaves its slot); Cmd+Z brings it back. `session head` → Clear empties the list; it asks first only if some assigned clip was not exported yet ("Clear 14 clips? 2 assigned clips are not exported yet."). A clip used by a queued or running export job (0143) stays until the job ends: that job works from its own snapshot.
- **Preview.** `clip preview` plays the selected clip (Space, seek on the waveform). Trim silence is per clip and optional, start only (first sound above −45 dBFS, 50 ms kept), shaded cut, Undo trim; no fades (0110).
- **Export.** For each assigned clip of the selected draft: `<name>.mp3` (LAME, 320 kbps CBR, 44.1 kHz) always, and `<name>.wav` (source rate, 24-bit if the source is, else 16) only for the clips whose `clip slot` has "WAV" ticked (Gio 2026-11-23: per clip, not per SKU; off by default); both folders remembered; re-export overwrites. Volume: exported as recorded, no normalization (parked by Gio 2026-11-23: peak normalize is fooled by vinyl clicks, and a limiter would change the sound on a club system; he DJs from WAV and MP3). Tags in every file (ID3v2.4; WAV in an `id3 ` chunk): title and artist of the line, album = record title, label, year (not a decade), genre, track = A1/B1, comment = SKU; cover = the side's label scan from the Labels folder (role 1 for A, 2 for B), square JPEG 1000 px; none if not scanned yet. No automatic upload: the MP3 320 goes into the admin by hand and becomes 128 kbps there (0108).
**Rule.** A clip's name comes only from the slot it is dropped on (names computed by the backend, 0136/0138); the app never renames or deletes files on the source card. Any count shown on a draft row reads what exists (files on disk, assignments), never a guess.
**Backend.** `scan-targets { id }` also returns `clips [{ role, label, name, artist, title }]` and `tags { album, label, cat_no, year, genres }`. Read only, no migration. Redeploy the function.
**Where.** Figma (design); `supabase/functions/scan-targets/index.ts`; the Mac Scanner app (`apps/scanner`, branch of PR #202) builds the tab.
