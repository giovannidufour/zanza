# 0107 — Admin Bulk create: many records from named files, as incomplete drafts

`2026-11-17` · accepted · Figma: BACKEND → `Bulk` (page 2344:6970): `bulk record` (device mobile | desktop × state reading | matched | choose | not found | confirmed | skipped, boolean `warning`), `unsorted file`, `bulk naming help`; frames mobile drop · overview · review one by one · drafts created (Listings), desktop overview

**Context.** Gio photographs and records many records in one go and wants to drop all the files at once: "the admin understands which record they belong to and creates the drafts". He then asked for a review "one after the other: Next, Next, Next, with Skip, and every state visible in the overview", and for the AI already used by Memo (0090) to help with the photos. Grading and price cannot come from files: Gio chose drafts that may be born incomplete.
**Decision.** New admin page `#bulk` (top bar "Bulk"). Files are named `<record>_<role>`: photos `_1 _2 …` (gallery order; photo `_1` is the one the AI reads, Gio 2026-11-17: "recognition from image 1, not from another"), samples `_a _b` (sides) or `_a1 _b2` (the line with that Discogs position); any other word = a photo at the end / an additional sample. A name without a valid role (`IMG_4471.jpg`: the role must be 1–2 digits, a word or a side + track) is "not recognised": an image is read by the AI and joins the record whose release matches; otherwise Gio picks its record in a select, or it stays out. Each record's photo 1 goes through read-label → discogs-lookup { fields } (one at a time); one result = matched, several = choose, none = not found. Overview = `BulkRecord` rows with their state, files, status and warnings (two samples for a side, no photos, a failed upload); **Review** walks the records still to review: label photo, files, Which record (the Memo picker, prefilled), **Next** confirms the picked release, **Skip** = no Discogs release; after the last one, back to the overview. **Create N drafts** saves one draft per record through admin_save_listing (Discogs fields as Fetch Discogs fills them; no release = line 1 titled with the prefix, no artist). The created ones leave the page and Listings opens with a toast; failed ones stay with the reason. Uploads start at the drop (3 at a time), like Create.
Migration 0026 (`20261117020000_incomplete_drafts.sql`): a draft may lack grading, format, price and the artist of line 1; the trigger `listings_publish_check` refuses any non-draft status without them ("incomplete draft: add the … before publishing"). A draft never published takes a new slug from its name on each save. The form's Save draft asks only for line titles; Publish asks for everything as before. Listings shows "Draft · Incomplete" and bulk Publish leaves incomplete drafts out.
**Rule.** A batch that creates records reviews them in the overview first (states always visible), and every record can be reviewed one by one with Next / Skip. What a listing needs to be live is checked when it leaves draft, in the database, never only in the form. A file name is a hint, never a requirement: what the name does not say, the AI or Gio decides.
**Where.** `apps/admin/admin.js` (Bulk, bulkParse, sampleLine, missingOf / incomplete in Listings, validate(f, status), RecordField id/label), `apps/admin/admin.css`, `packages/ui` (`BulkRecord`, `BulkHelp`), `supabase/migrations/20261117020000_incomplete_drafts.sql`.
