# 0030 — The admin shows a live shop preview, built from the shop's components

`2026-11-10` · accepted · Figma: BACKEND → Create › `side` › `preview` (2133:933, frame `shop preview` 2110:24523)

**Context.** Gio wants to see what he is creating while he fills the Create listing form. He drew the PDP - mobile content (gallery + product info, no header, no Add to bag) and asked to put it in the Create frame. It sits in the side column under Sku, 315 wide, with its explicit Figma mode `frontend` (acid green) inside the `backend` page.
**Decision.** The preview renders the same `Gallery` and `ProductInfo` (device=mobile) as the PDP, fed by the form state through the shop's own text mapping (name, release info, price, grading: mirrored in `apps/admin/admin.js` → `previewName` etc.). It updates on every keystroke; empty parts are left out. A Figma frame with an explicit mode is a nested `data-theme`: `build-tokens.js` now also emits a `[data-theme="frontend"]` block (all per-mode tokens), so the first theme can be nested inside another. `ProductInfo` gets `headingLevel` (default 1) so the preview title is not a second `<h1>` in the admin.
**Rule.** Previews of shop content reuse the shop components and mapping, never a lookalike; a different Figma mode on a nested frame = `data-theme` on that container. If the shop mapping changes (`apps/storefront/pages/shell.js`, `data/products.js`), change the preview mapping with it.
**Where.** `apps/admin/admin.js` (shopPreview, preview* helpers), `apps/admin/admin.css` (.admin-preview__shop, side column scroll), `packages/ui/build-tokens.js`, `components.js` (ProductInfo headingLevel).
