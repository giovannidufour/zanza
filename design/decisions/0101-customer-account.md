# 0101 — Customer account: email code, orders found by email

`2026-11-15` · accepted (Gio: "account light con codice OTP", then "si parti") · Figma: page `Account` (2198:2395), components `order row` (2198:2509), `order item` (2198:2462), note "account behaviour"

**Context.** Gio's requirement: a customer signs in and sees their orders and their status. The shop is a private seller with minimal legal pages, guest checkout through Stripe, and a static site.
**Decision.** An account is the customer's verified email, nothing else: sign in with email + 6-digit code (Supabase Auth email OTP; no password, no profile, no address book). Orders are matched by `lower(email)`, so guest orders show up without any linking step. Only an email with at least one order can get an account (Auth hook, migration 0022): no empty accounts. The code request answers the same whether or not the email has orders, so the page never reveals who bought here. Three static pages: `/account/` (orders), `/account/order/?id=…`, `/account/details/` (email, sign out, download my data as JSON, delete account). Order lines come from a snapshot taken when the order is written (`order_items.snapshot`), not from the live listing. Statuses shown: Paid, packing · Shipped (date, tracking number) · Refunded · Cancelled; no Delivered. Header Account links to `/account/` (state active there, as Bag, 0045); the menu's Account detail shows the signed-in email.
**Rule.** Personal data never goes into the static HTML: account pages are shells filled in the browser from `<template>`s rendered by packages/ui. A new account feature stays read-only on orders unless Gio asks otherwise.
**Where.** `apps/storefront/pages/account.js`, `account.css`, `scripts/account.js`; packages/ui `OrderRow`, `OrderItem` (= BagItem without Remove), Tab `size="extra-small"`; `supabase/migrations/20261115030000_customer_account.sql`.
**Deviations from Figma (by Claude, to confirm).** Order reference = the 8-character ref of the emails and the admin (0100), not "1042" · no "Track parcel" (orders have no carrier yet) · no "Change email" (orders are found by email: a new email would lose them) · copy: sign-in intro no longer says "create an account"; "German tax law … 10 years" removed (private seller); "Addresses stay with Stripe" corrected (the order keeps the shipping address); the help text drops "we reply within 2 working days".
