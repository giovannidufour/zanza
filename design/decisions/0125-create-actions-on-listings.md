# 0125 — Create listing and Bulk create are actions of the Listings page

`2026-11-22` · accepted (Gio: "in admin create listing e bulk create dovrebbero stare solo nella pagina listings, non nella navigazione principale") · amends [0089](0089-admin-mobile.md) (navigation) and [0107](0107-admin-bulk-create.md) (entry point) · Figma: COMPONENTS → `admin` → `admin bar` (2299:1883, `create` removed from both variants); new component set BACKEND → Listings → `listings head` (2406:2280, device desktop | mobile), used in every Listings frame and in Bulk → `Bulk - mobile · drafts created (Listings)`

**Context.** The admin bar mixed two kinds of thing: places (Listings, Orders, Memo…) and actions (Create listing as a primary button, Bulk as a section in code). Both actions add records to Listings, so they belong to that page; in the bar they competed with the navigation and the mobile bar had a third button.
**Decision.** The admin bar holds only places: desktop = section buttons · email + Sign out; mobile = Menu · "Store admin". Bulk is no longer a section (it was in code, never in Figma). The Listings page head (`ListingsHead`) = title + Bulk create (secondary) + Create listing (primary), gap 16; desktop one row with the actions on the right, mobile the actions under the title (the uppercase labels do not fit beside "Listings" at 343). The routes `#new` and `#bulk` keep working; while on them (and on `#edit-<id>`) the bar marks Listings as current, `#new/memo/<id>` marks Memo.
**Rule.** The admin bar and menu list places only; an action that creates something lives on the page of the list it adds to, in that page's head.
**Where.** `packages/ui` (`AdminBar` without `createHref` / `createLabel` / `createShortLabel`, new `ListingsHead`, `components.d.ts`), `apps/admin/admin.js` (`SECTIONS`, `sectionOf`, `Nav`, Listings).
