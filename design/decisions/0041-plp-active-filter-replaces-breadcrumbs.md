# 0041 — PLP: no breadcrumbs, only the filter reached from a link

`2026-11-10` · accepted (Gio) · Figma: page `active filter` → `active filter` (2166:6183, device=desktop | mobile); PLP frames "PLP - desktop / filtered by label" (2145:5835), "PLP - mobile / filtered" (2148:6141); `breadcrumbs` lost its `active filters` boolean

**Context.** On the PLP the breadcrumbs were "For sale / ticked options / [artist or label chip]". The section is already in the header tabs and the h1, and with For trade a section crumb says nothing more; the ticked options are already in the filter column (desktop) and in the layer (mobile).
**Decision.** PLP only: the breadcrumbs go; their place shows the filter reached from a link, as one removable entity chip (medium desktop, large mobile), with the breadcrumbs' frame (padding `small`, 1px rule `border divider/strong`). Links: artist and label (no checkbox) and, new, the subgenre / tag links on cards ("Subgenre: Roots", "Tag: Rare"); a new link click replaces it. A subgenre / tag counts as linked only when the page opened on that single value (kept in history.state, so reload and Back keep it); ticking the same option by hand makes no chip. Removing the chip unticks it. No link filter → no row (the list moves up). The mobile layer still lists every applied filter. The PDP keeps its normal breadcrumbs (it never shows a filter).
**Rule.** Breadcrumbs only for a real path (PDP). A single active state above a list is a labelled group (`role=group`), not a `nav`.
**Where.** `packages/ui` `ActiveFilter` (new), `Breadcrumbs` (`active` removed); `apps/storefront/pages/plp.js`, `scripts/site.js`.
