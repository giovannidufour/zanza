# 0089 — Admin on mobile: bar + menu, rows instead of tables, actions at the bottom

`2026-11-15` · accepted · Figma: COMPONENTS → `admin` (page 2299:1725): `admin bar` (device desktop | mobile), `admin menu`, `listing row`, `bulk bar`, `action bar`; BACKEND → Listings: `Listings - mobile`, `· selection`, `Admin menu - mobile · open`; BACKEND → Create: `Create listing - mobile`, `· viewport (sticky actions)`

**Context.** Gio wants to build listings and browse the admin from the phone (photograph a record, list it). At 375px the admin was a desktop page squeezed: the top bar took three rows, the tables ran off the screen (505px), Publish / Save sat above 2800px of form, Shipping's fixed columns did not fit, Label overlapped Country (fixed in #120).
**Decision.** One breakpoint (`--mobile`, 0004); the JS that must render differently reads the same query (`config.js` → `media.mobile`, from tokens.json by `build.js`).
- **Navigation** (Gio's choice, 2026-11-15): `AdminBar`. Desktop = the section buttons (Listings, Memo, Attributes, Shipping; the current one in Button state=active, 0045) + Create listing · email + Sign out (the bar is now drawn). Mobile = Menu button · "Store admin" · Create (primary, 38). Menu opens a full-screen native `<dialog>` with the shop's `MenuLayer` (0060): sections (current = `menu item` state=current) and Sign out with the email as detail (`MenuItem` without href = a button). Esc, × or a link closes it; focus returns to the Menu button.
- **Lists** (Listings, Attributes): on mobile `ListingRow`s in a `<ul>` instead of the table, the MemoItem grammar (0087): checkbox · title link + meta (SKU · status · section) · price. The bulk bar follows the rows and, while something is selected, sticks to the bottom of the viewport (surface/base, top border); with nothing selected it shows only the last result. Status tabs stay on one row and scroll sideways.
- **Forms** (Create / edit, attribute): one column in form order; the side (SKU, status, preview, View in store) follows the form. Primary + secondary action in `ActionBar`, sticky at the bottom of the viewport (surface/base: surface/subtle is translucent in the backend mode), with the save result above the buttons; `scroll-padding-bottom` keeps a focused field above it.
- **Shipping**: the tables stack, one row = a block of fields with the column name above each (`data-label`).
- **Targets**: on a coarse pointer, small Buttons and checkboxes get an invisible 44px tap area; nothing changes visually.
**Rule.** Every admin page works at 375px without horizontal scroll. A table on the admin becomes `ListingRow`s on mobile (or stacked labelled fields when its cells are inputs); a form's main actions go in an `ActionBar` on mobile; new admin sections are added to `SECTIONS` in admin.js (bar + menu together). Fixed bottom bars are opaque (surface/base).
**Where.** `packages/ui` (`AdminBar`, `ListingRow`, `ActionBar`, `MenuItem` as button, touch targets), `apps/admin/admin.js` (`Nav`, `useIsMobile`, Listings, Attributes, ListingForm, AttributeForm, Shipping `table`), `apps/admin/admin.css`, `apps/admin/build.js`.
