# 0196 — Scanner Price tab: sale type, price and conditions of a draft, written to the listing's own columns

`2026-11-26` · proposed · Figma: BACKEND → `Scanner`: section `price · components` (`price panel` = the Create page's Price block with `price fields` + divider + Conditions block, `price fields` exposed; `price save` = "In the shop" preview lines, Save, Save and next, status); `scanner tabs` gets a third tab and `mode=price`; `media status` gets `kind=price` (some | partial | none) with its own TEXT property `price`; `draft row` shows it after the clips chip; screens "Scanner v3 - price tab, editing" (2601:16571) and "Scanner v3 - price tab, best offer, no cover" (2601:18220)

**Context.** Gio (2026-11-26): besides Scans and Samples, a tab in the Scanner where he enters prices and conditions of his drafts. Until now they could only be typed in the admin's Create / Edit form, one record at a time.
**Decision.**
- **Third tab "Price"** (⌘3). Same three columns as 0141: left = the drafts list (unchanged, search filters it); centre = the admin's Price and Conditions blocks, the same fields, labels and choices (Sale type: For sale / Best offer / For trade, For trade only while the Trade switch is on (0102) or the draft already is trade; Price € (optional for trade, none for Best offer, 0158); Side A, Side B (optional), Conditions comment (optional), Cover (Original / Generic / None), Cover conditions (optional, hidden with None)); right = `draft head`, then `price save`: "In the shop" (the lines the shop shows, same rules as `gradingProps` / `priceText`), Save (⌘S) and Save and next (⌘↩: saves, then opens the next draft of the list).
- **Single source of truth.** The app reads and writes the listing's own columns (`section`, `price_mode`, `price_cents`, `condition_media`, `condition_media_b`, `condition_notes`, `sleeve_type`, `condition_sleeve`) through PostgREST with the admin's session (RLS `listings_admin`, the grant the admin form already uses). Nothing is stored in the app; no Edge Function, no migration. Only these columns are written: release, lines, photos and samples are untouched. Empty values are stored as null, as `admin_save_listing` does; a draft may stay without price or grading (0107), publishing still checks them (`listing_publish_check`).
- **Unsaved edits are kept per draft** while switching drafts ("Not saved yet" in the status); nothing is written without Save.
- **Draft row chip** `media status` kind=price: "€" + "price · side A grade" ("25 · VG+", "Offer · VG+", "Trade · VG+", "– · VG", "–"). Green = priced (or Best offer / trade) and graded, orange = one of the two, red = neither. The text says it without colour (1.4.1); the tooltip lists what is missing.
- Update (⌘R) re-reads price and conditions of the listed drafts, so an edit made in the admin shows up.
**Rule.** A field the Scanner shows for a listing is the admin's field on the same column, with the admin's labels and choices; the app never keeps its own copy of listing data.
**Open.** (1) `€` is a text glyph in the chip: no tag icon in the library · (2) the active tab is still not drawn in Figma (0141 open item; code = primary button) · (3) a draft open in the admin form at the same time is overwritten by whichever saves last (same as two admin tabs).
**Where.** `apps/scanner/Sources/Pricing.swift` (model + views), `Backend.swift` (terms, saveTerms, tradeEnabled), `AppModel.swift`, `ContentView.swift`, `SamplesViews.swift` (tabs), `AdminPanel.swift` (chip), `DraftSession.swift` (Update).
