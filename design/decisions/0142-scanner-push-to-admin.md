# 0142 — Scanner: Push to admin, a button next to the SKU that attaches the draft's scans and clips in the admin

`2026-11-23` · proposed · Figma: BACKEND → `Scanner`: section `samples · components` → `push status` (state push | pushing | synced | failed), `draft row` (new boolean `push`, `head` = SKU + `push status`), `push · replace confirm` (instance of `dialog`); icons `icon/icon-upload`, `icon/icon-upload-done` (page icons)

**Context.** Until now the Scanner only names and exports files (0138, 0141: "no automatic upload"); Gio then drops them into the admin by hand. He asked (2026-11-23) for a small button next to the SKU in the drafts column that sends that draft's images and clips to the admin, and then shows a "synced" icon.
**Decision.**
- **Manual only.** Nothing leaves the Mac until Gio presses the button of that draft. The button sits at the right of the SKU line of the `draft row`, in both tabs (the drafts column is shared, 0141). Hidden (`push` off) on a draft with nothing to push.
- **States** (`push status`): *push* = never pushed, or a slot changed since the last push; *pushing* = upload running, button disabled; *synced* = the admin holds exactly what the slots hold; *failed* = last push failed, press to retry (the error as tooltip / status line). The icon has an accessible label ("Push SKU 48213 to the admin", "SKU 48213 synced") and a 24×24 target.
- **What is sent.** Images: every filled image slot, by role (1 Label A, 2 Label B, 3… other photos), converted as the admin does (WebP q 0.86, long side 1600 + copies 200/400/800, `packages/images`). Clips: every filled clip slot, MP3 **128 kbps** for the shop (0108), encoded from the session source; the MP3 320 and the WAV stay local. Upload through `sign-upload` (same as the admin: random immutable keys), then `scanner-push` attaches the keys to the draft.
- **Ask each time** (Gio 2026-11-23, decision card). Before pushing, the app calls `scanner-push { id, check: true }`. If the admin already has a photo for a pushed role or a clip for a pushed line, the `dialog` lists them ("Replace in the admin?" · Cancel / Replace and push); otherwise it pushes without asking. Confirmed = replace those roles/lines; roles and lines not pushed stay as they are.
- **Synced is local truth.** The app stores, per draft, a hash of each pushed slot file and the keys returned; *synced* = same hashes now. A change in the admin after the push is not tracked (the admin stays the place to edit; pushing again asks again).
**Rule.** The Scanner never writes the database itself: one Edge Function (`scanner-push`) owns how keys land on a draft, as `scan-targets` owns the names. Drafts only. Old files are never deleted from storage by a push.
**Backend.** New Edge Function `scanner-push` (admin session, Verify JWT ON): `{ id, check }` → what the admin has; `{ id, mode: "replace" | "fill", photos: [{ role, key }], clips: [{ line, key }] }` → sets `listings.photo_keys[role-1]` (gaps closed) and one `samples` row per line (A, B… positions, line order, typed titles kept), as `admin_save_listing` does. No migration (admin RLS already allows it). `scan-targets` clips also return `line` (1-based). Deploy both.
**Where.** Figma; `supabase/functions/scanner-push/index.ts`, `supabase/functions/scan-targets/index.ts`; the Mac Scanner app (`apps/scanner`, PR #202 branch).
