# 0169 — Delete an order from the admin, with a confirm dialog

`2026-11-24` · accepted (Gio: "vorrei poter eliminare gli ordini dall'admin. Fallo attraverso un alert di conferma") · amends 0100 · Figma: BACKEND → Orders → `Order - desktop` (2322:5724, panel `secondary 2` on), `Order - mobile` (2322:6518, `delete order` button 2526:708), `Order - delete dialog` (2526:724, COMPONENTS → `dialog` with `choices` on)

**Context.** Stripe test-mode orders (and mistakes) piled up in Orders, and their records stayed sold. The admin could only read orders and mark them shipped.
**Decision.** The order page gets a secondary **Delete order** button: the last button of the action panel on desktop, under the tracking field on mobile. It opens the `dialog`: title "Delete order <REF>?", body "It goes from Orders and from the buyer's account. Stripe keeps the payment: refund it there if needed. It cannot be undone.", and, when the order has records still sold, a required pick: **Put N records back on sale** (default) or **Keep N records sold** (default on a shipped order, the record has left). Confirm = `admin_delete_order(order, restock)` (migration 0036, security definer + `is_admin()`): deletes the order and its items; with restock, only the copies still `sold` go back to `available` (status log note "order deleted"; the shop rebuilds by itself). A copy that moved on since stays as it is. Stripe is never touched (no refund, no cancel). Then back to Orders with a toast "Order <REF> deleted. N records back on sale."
**Trade-off.** An order was an accounting record (backend.md → Elimina). For a real sale the payment record stays in Stripe; delete is meant for test orders and mistakes, and the dialog says it cannot be undone.
**Rule.** Deleting something that changed other rows (here: copies sold) asks in the same dialog what happens to them, with the safe default for the item's state; never a second dialog.
**Where.** `apps/admin/admin.js` (`OrderDetail`: `askDelete`, `doDelete`, dialog), `supabase/migrations/20261124000000_delete_order.sql`.
