# 0174 — Curated collections: cards under the home intro, a PLP per collection, set up in admin → Collections

`2026-11-24` · accepted (Gio: "una serie di card minimal, stile banner, che puntino a determinate categorie… configurabile dall'admin… possa gestire l'ordine"; design approved "va bene, procedi") · amends [0120](0120-home-v2.md), [0028](0028-plp-filters.md) · migration 0038 · Figma: page `Home` → `collection card` (state default | hover, TEXT `label`) and `home collections` (device desktop | mobile) in the frame `collections` under the intro; page `PLP` → `PLP - desktop / collection` + note; page `Collections` (BACKEND, after Attributes) → `collection row` (type head | row, boolean `handle`), `Collections - desktop`, `Collection - desktop · edit (Oldies)`, note `collections`

**Context.** Gio wants to point the home to curated groups of records (e.g. Oldies = 1960s + 1970s, Digi = tags Digi + Dancehall Digi, Riddim Pick = tag Riddim Pick) and change them himself.
**Decision.**
- A **collection** = name + slug + **rules**: Years (a year "1983" or a decade "1960s", 0082), Genres, Tags. A record is in when it matches every rule filled in; inside a rule any value is enough (the PLP filter logic, 0028). At least one rule. Genres and tags are stored by id, so a rename keeps the collection.
- **Home**: under the intro, full width, the collections set to "Show on the home", in Gio's order: `collection card` = a link box, label centered (label/large), 1px border divider/strong, padding medium-small, min height 96, hover surface/hover. Desktop 4 per row (a card = the 3-of-12 side column), mobile 2 per row, wrapping. No collection on the home → no row.
- **Page** `/collections/<slug>/`: the sale PLP (filters, sort, Show sold out) with the sale records that match; heading "Oldies (23)" (`search heading`). A collection with 0 records keeps its card and its page shows "Nothing in this collection right now." + Browse all records (Gio: he wants to see it, to judge the strategy).
- **Every PLP** (/sale/, /trade/, /catalog/, search, wantlist, collections): records for sale first, sold ones at the end, both in the listing order; the price sorts keep the same split (Gio 2026-11-24). Reserved copies stay with the ones for sale.
- **Admin → Collections** (nav after Attributes): the list in the order of the cards, drag & drop to reorder (handle, as Listings 0129); columns Name, Rules, On home, Records. The edit page: Name, Slug, Rules (Years as free chips, Genres and Tags from the existing ones), Show on the home; Save / Delete; on the right the records that match now (sale copies the shop can show, sold at the end), recomputed while typing.
- Rule types are years, genres and tags only for now; format, label, price may come later (Gio: "può essere").
**Rule.** Which records are in a collection is decided in one place, `packages/collections/collections.js`, used by the shop build and the admin; a new rule type is added there, in `public.collections` and in the edit page together. Every PLP lists the records for sale before the sold ones.
**Where.** `supabase/migrations/20261124100000_collections.sql` (table `collections`, admin RLS, `admin_order_collections`, rebuild trigger), `packages/collections/collections.js`, `packages/ui` (`CollectionCard`, `HomeCollections`), `apps/storefront/data/products.js` (`loadCollections`), `apps/storefront/build.js` (`collections/<slug>/`, `Plp.soldLast`), `apps/storefront/pages/plp.js` (`collection`, `soldLast`), `apps/storefront/pages/home.js`, `apps/storefront/scripts/site.js` (`applySort`), `apps/admin/admin.js` (`Collections`, `CollectionForm`), `apps/storefront/content/collections.json` (examples for the JSON build).
