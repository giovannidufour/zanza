# 0020 — Entity fields are chip inputs (the `input` with chips)

`2026-11-10` · accepted · Figma: `input` → `_input-master` › `chips` + `chips content` (`_input chips`), `entity chip` (page tags), `entity option` (page input › building blocks); examples on BACKEND → Create (2106:676)

**Context.** Artists, labels and tags are entities (migrations 0006, 0007), clickable later (artist and label pages, PLP filters). With the native datalist (0019) it was not visible whether a field was bound to an entity or was free text, and a line could hold only one artist.
**Decision.** Gio (2026-11-10): the fields work "like tags/chips". Each chosen entity is a chip (`entity chip` = `tag item` medium + a 24×24 remove ×); text that is not a chip is not a value. Typing opens a menu below the field (`entity option`: existing entity · alias "spelling → official" · "Create “…”" always last unless the exact name exists). Artist and Tags take several chips (a line's artists are joined "&"), Label one (the text box is hidden while it is set). In Figma the field is the existing `input` (no new variants): boolean `chips` shows the `_input chips` building block before the value, `chips content` swaps it; the field padding is overridden to 6 so it stays 38px.
**Rule.** Any field whose value is one or more entities is `EntityField` (WAI-ARIA combobox + listbox: arrows, Enter, Escape, Backspace removes the last chip; leaving the field turns an exact official name into its chip). Never a datalist, never comma-separated text. "Different spelling" stays a separate field next to the chips (one printed credit per line or release).
**Where.** `packages/ui/components.js` (`EntityField`, `EntityChip`), `apps/admin/admin.js`, `supabase/migrations/20261110050000_tags_chips.sql`. Supersedes [0019](0019-entity-suggestions-are-native.md).
