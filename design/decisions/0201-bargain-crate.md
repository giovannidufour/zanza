# 0201 — Bargain crate: a third shop section for cheap records, hidden on the other PLPs until ticked

`2026-11-27` · proposed · Figma: `header` (2006:8941, third tab in the tab group), `menu layer` (2200:1690), `footer links` group=shop (2261:3), `filters` (2052:16051) and `filters layer` (2148:6123) boolean `show bargain crate`, `product card` (2050:12869) boolean `samples`, `price fields` (2362:4410) boolean `bargain crate`; screen PLP → `PLP - desktop / bargain crate` (2618:48584) + note

**Context.** Gio (2026-11-27): cheap or less interesting records go in a "bargain crate", as basic listings (one phone photo, no samples, Take photo 0200), kept apart so the curated part of the shop stays clean. He asked for a section called Bargain crate, for now a third item in the header next to For sale and For trade (he will move it later), a tick on the PLPs to show or hide the crate, off by default, and a flag in the admin.
**Decision.**
- **Data**: `listings.bargain boolean not null default false` (migration 0046). Only a fixed-price sale copy can be in the crate (the admin saves false otherwise).
- **Admin**: Create / Edit listing → Price → Checkbox `Bargain crate` under Sale type and Price (`PriceFields` slot `bargain`), shown for For sale only (not Best offer, not trade). Saved with the listing row, like the title links; a duplicated copy keeps it.
- **Shop**: `/bargain-crate/` = a PLP of the sale records flagged (available, reserved, sold; sold last as 0174), title and tab "Bargain crate", price sorts, the same filters; no "Show bargain crate" row there. Header tab after For trade (always shown), mobile menu item after For trade, footer Shop link after For trade. A bargain record's PDP lights the Bargain crate tab.
- **Other PLPs** (For sale, search, collections, wantlist, catalog): the bargain records are in the HTML but hidden; the row `Show bargain crate` (a `filter` like Show sold out, unticked) shows them; ticked = `?bargain=show`. It never counts as an applied filter; Reset unticks it. The row is there only when the page has bargain records. Built page 1 and its pagination count the records shown by default.
- **Kept out of the curated part**: the home (genres, This week, Recent) and "More for sale" on a curated record's PDP leave bargain records out; a bargain PDP still suggests any record.
**Rule.** A bargain record is shown by default only on `/bargain-crate/` and on its own page; anywhere else it needs the visitor's tick (`isBargain` in pages/plp.js, `data-bargain` + `?bargain=show` in scripts/site.js).
**Open.** (1) Search and wantlist hide bargain matches by default too (as asked): a visitor looking for a specific record may get 0 results while it sits in the crate · (2) the Figma PLP screens at 1024 px cut the Bag button with three tabs (the site fits: the logo shrinks) · (3) no mobile screen of the crate page in Figma (same PLP components) · (4) Listings in the admin don't mark bargain copies.
**Where.** `supabase/migrations/20261127100000_listing_bargain.sql`, `apps/storefront/pages/plp.js`, `shell.js`, `home.js`, `pdp.js`, `build.js`, `data/products.js`, `scripts/site.js`, `packages/ui` (`PriceFields` `bargain`), `packages/listing-draft` (`bargain` in the form), `apps/admin/admin.js`.
