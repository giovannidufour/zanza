# 0138 — Scanner v2: picks an admin draft, images ordered by drag, fluid drag/turn with guides

`2026-11-22` · proposed · Figma: BACKEND → `Scanner`: section `v2 · components` (`orientation glyph`, `angle badge`, `rotate guides`, `draft result` state default | hover | selected, `draft picker`, `draft head`, `image slot` state filled | target | empty | dragging, `sign in` step email | code, `image lightbox`), `scan preview` new state `rotating`; screens "Scanner v2 - sign in / pick draft / turning / reordering"; frame "notes · v2 behaviour, keyboard, admin link"

**Context.** The macOS Scanner v1 (decision 0137, still only in the Mac copy) scans a 4" label crop + the original and takes its names pasted from the admin's "Copy all" (0136). Gio's feedback on v1, 2026-11-22: dragging and turning the image is very slow; he wants a rotation aid like Apple Preview (an upright figure) and horizontal lines to align the label text; arrow keys to fine-tune the position; and the app should query the admin: search the drafts, pick one, decide which scan is image 1, 2, 3… with drag and drop, the order defining the file name. No automatic upload or draft change for now.
**Decision.**
- **Fluid drag/turn.** During a gesture the app moves a proxy (Preview downscaled once to max 1200 px, a GPU layer); position and angle are a layer transform only. The full-resolution image is used once, on Scan, off the main thread. Auto-rotate (OCR) also runs on the proxy.
- **Rotation aids.** `orientation glyph` turns with the image (upright = label reads correctly). `rotate guides`: horizontal lines 24 pt apart, fixed to the window, shown only while turning and 600 ms after. `angle badge` with the live angle, 0.5° steps, soft snap at 0/90/180/270 (±1°).
- **Keyboard.** Preview focused: arrows move 0.5 mm, Shift+arrow 5 mm; `[` `]` turn 0.5°, Shift 5°; Cmd+0 resets; Return = Scan. Image list: Option+Up/Down reorders.
- **Admin link.** Sign in with the admin email (Supabase email OTP, same allow-list, session in the Keychain). `draft picker` searches drafts only (SKU, artist, title, cat. no.), read only. The picked draft shows `image slot`s: 1 Label A, 2 Label B, 3 Other photo, then 4, 5… appended by a Scan when all are filled; position = role = file name (0136). The next Scan fills the target slot (first empty); dragging a row reorders and renames the files on disk at once (label crop + original); x moves both files to the Trash. Offline or signed out, v1's manual name field stays as the fallback.
- **Window (Gio 2026-11-22, "too compressed and chaotic", search sacrificed).** 1440×900 on the cream ground of the admin (`surface/page`), three columns: Drafts 360 (search always visible + results, picked draft = `draft result` selected, no Change draft) · preview 720 · picked draft 360 (`draft head`, `image slot`s, File name, Preview | Scan, settings, scanner status). Figma: "Scanner v2 - wide, search column" (2437:1540); "Scanner v2 - wide (3 columns)" was the step before.
- **Image list legibility (Gio 2026-11-22: "3 items but I scanned nothing").** `images head` ("Images · N of M scanned") above the list. `image slot`: filled = check; target = tag "Next scan"; empty = "Not scanned"; only scanned rows have a drag handle and reorder; removing a scan = Delete / context menu. A name is a preview until Scan; Scan writes both files at once; reordering renames them at once.
- **Rows are not selectable (Gio 2026-11-22 23:47, "selecting the card only messes up the layout").** No selected/click-to-target state: the target is always the first empty slot. A scanned row has an x (`icon button`, icon-x) that deletes that scan (both files to the Trash, Undo in `images head`). Clicking a scanned thumbnail opens `image lightbox` (scrim + panel with role, file name, the scan large; Esc or x closes, ←/→ = previous/next scan). No Add image: a Scan when every slot is filled appends the next row (4, 5…). Figma: "Scanner v2 - lightbox (click a scanned thumbnail)" (2441:24973).
**Rule.** In the Scanner a file's role comes only from its position in the image list of the picked draft; the app never builds the slug itself, it takes the names computed by the backend (single source of truth of 0136).
**Backend (Gio ok 2026-11-22, built).** Edge Function `scan-targets`, read only, admin session JWT: `{ query }` → up to 20 drafts; `{ id, roles }` → the names of image roles 1…N. The rule moved from `apps/admin/admin.js` to `packages/file-names/file-names.js`, used by the admin and copied into the function (`npm run sync:functions`). No migration. See `_context/backend.md` → Scanner.
**Where.** Figma (design); `packages/file-names/`, `supabase/functions/scan-targets/`, `apps/admin/admin.js` (fileNamesOf); the Mac Scanner app (not in this repo) builds the search and the slots.
