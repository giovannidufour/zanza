# 0106 — Admin Content: Gio edits the shop's texts in his own voice

`2026-11-17` · accepted · Figma: page `Content` (BACKEND, after Settings): components `content group head`, `content row`, `content editor head`, `link row`, `step row`, `admin page intro`; screens Content - desktop / mobile, Content - desktop · Profile, Content - desktop · Shipping, Content - mobile · Contact; note "content behaviour"

**Context.** Gio (2026-11-17): today every text change on the shop goes through Claude; he wants an admin section to manage his info and the small texts himself. Today these texts live in `site.json` (owner, comingSoon), `content/legal/*.md` and as constants in `pages/*.js` (trade pitch, How trading works steps, contact, bag and checkout notes, newsletter messages).
**Decision.**
- New admin section **Content** (`#content`), in the bar and the menu after Settings.
- Editable = texts in Gio's own voice. Interface text (buttons, labels, errors, empty states, the grading scale) stays in code: changing it can break flows and the design system owns it.
- Three groups on the list page, one `content row` per editable block (title, where it shows, last edit, Trade only flag, Edit):
  - **About you** — one structured Profile: name (signature), DJ name, bio (plain text, empty line = new paragraph), links (label + URL, ordered, Add / Remove), Discogs username + card line, Instagram username, Facebook profile link. Message links (Discogs compose, ig.me, m.me) are derived from these, not typed.
  - **Pages** — Grading, Shipping, Terms, Privacy, How trading works, each edited as a list of sections in the order of the page (`section row`: heading + text, Remove, Add section), so it is clear where each text goes (Gio 2026-11-17). Text: plain, with `**bold**` and `[link](url)` only; no Markdown headings or blocks to learn. Page title (H1) and URL are fixed. How trading works uses the same row for its steps.
  - **Short texts** — plain text fields grouped by shop page: Record page, Bag and order confirmed, Contact, Make an offer (incl. reply days), Newsletter, Coming soon.
- Editor page per block: `content editor head` (back to Content, title, "Shown on", View on shop, Save); mobile = Save and View on shop in the `action bar` (0089).
- Save = one save per block, then the shop rebuilds (deploy hook, ~2 min) as Settings (0102). Toast "Saved. The shop updates in about 2 minutes." No drafts, no scheduling, no preview build.
- Placeholders: `{{…}}` are filled by the shop (countries, email) and must survive a save (refused inline otherwise); `[[p:…]]` marks a value still to confirm; `{{#trade}}…{{/trade}}` works in every text, as in the legal pages.
- Trade-only blocks stay editable while trade is off; the row says "Trade only: hidden on the shop while trade is off".
- Storage: `public.site_texts` (key → value jsonb, migration 0025), read at build like `shop_settings`; Save = `admin_set_text` (rebuild). A block or field never saved = today's text in the repo (`packages/content/content.js` defaults: site.json → owner, `content/legal/*.md`, constants), so nothing changes until Gio saves. Saving Privacy sets its "Last updated" date.
- Who I am in the database: `shop_settings.identity_enabled`; `trade_enabled` becomes a generated column (`trade_wanted and identity_enabled`), so the build, RLS and the trade functions follow without changes.
- v1 blocks: Profile, Store profile, Shipping, Terms, Privacy, How trading works, Contact, Order confirmed, Trade (record page and offer). Not yet: Grading (the page /grading/ is linked but does not exist yet), newsletter messages, coming-soon page, emails.
- **Who I am switch** (Gio 2026-11-17: launch quietly, without his person; switch it on later for trust). One setting in Settings, `identity setting` above Trade, same pattern as 0102 (`shop_settings`, Save → rebuild). About you holds two blocks: **Profile** (shown while on) and **Store profile** (shown while off: About text and the shop's own links, no names). Off = no name, DJ name, bio, signatures ("— Gio" on trade notes and the offer page), Discogs card, personal Instagram / Discogs / Facebook links (About, home, footer Follow). Trade relies on Gio's identity (Discogs card, verification password sent to his profiles), so switching identity off switches trade off too. Content rows carry the condition ("Shown while “Show who I am” is on / off").
**Rule.** A new text in Gio's voice goes in Content (a field of an existing block, or a new row) instead of a constant in a page; interface text stays in code. Every Content text follows the trade switch through `{{#trade}}…{{/trade}}` or a Trade only block.
**Where.** `supabase/migrations/20261117010000_site_texts.sql`, `packages/content/content.js`, `packages/ui` (ContentGroupHead, ContentRow, ContentEditorHead, LinkRow, SectionRow), `apps/admin/admin.js` (Content, ContentEditor, Settings), `apps/admin/build.js`, `apps/storefront/build.js`, `data/products.js`, `pages/shell.js` (textOf, identityOn), `trade.js`, `contact.js`, `checkout.js`, `home.js`, `legal.js`.
**Staging edit links (2026-11-17).** On staging every page with editable texts starts with a strip of secondary small Buttons (✎ + block title) that open that block's editor in the admin in a new tab (`site.json → targets.pages → editLinks`, shown only while `noindex`). Not in Figma: a staging tool, not shop UI. In-page editing (popup on the page) was judged not worth it: the admin editor already validates and saves.

**Open.** Who I am off still leaves Gio visible in: the shop address `gio@rythem-works.com` (his first name; site, Resend sender, Privacy), Stripe Checkout's public business name and statement descriptor of his Individual account (to check in Stripe), the Privacy page controller (`{{legal.name}}`, today empty; GDPR expects the controller to be identifiable: legal check before launching anonymous), `privacy-coming-soon.md` ("run by Gio").  Markdown vs a small formatting toolbar for Pages; emails (order, offer, notify) not in v1; the coming-soon page reads Content only if its build can reach Supabase. See [`../open.md`](../open.md).
