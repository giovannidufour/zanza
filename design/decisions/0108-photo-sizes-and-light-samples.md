# 0108 — Photo sizes (srcset) and lighter samples, made in the admin at upload

`2026-11-17` · accepted · Figma: none (no visual change on the shop). Admin Settings → `Photo sizes` is not drawn yet (design/open.md)

**Context.** Every spot of the shop loaded the same 1600 px photo: a 96 px card on a phone, the 48 px player cover, the bag. Gio asked for "the images at the right size for each spot, to make the site lighter", and for samples uploaded at 320 kbps to become 128 kbps by themselves. Free tiers only: no paid image service, no server-side image processing.
**Decision.** The admin makes everything in the browser before the upload. **Photos**: the photo itself (webp, long side 1600) plus copies with long side 200, 400 and 800, next to it in R2 with the width in the key (`photos/<uuid>-w400.webp`; never enlarged). One list of widths in `packages/images/images.js`, used by the admin, the storefront build and the Edge Functions (copied by `supabase/scripts/sync-functions.js`). `sign-upload` signs a copy key only for an existing photo key and a known width (`{ of, width }`); `purge-media` deletes the copies with their photo. The copies go up smallest first after the photo, so the last one (`-w800`) existing means all exist; a copy that fails does not fail the photo. The storefront build checks that last copy for every photo (one HEAD each) and only then writes `srcset` (copies + the photo as `1600w`) and `sizes` (card: 96px on mobile, 16vw on desktop; PDP gallery: 100vw / 33vw; bag and order row 96px and player 48px are fixed, as component defaults). The player and the trade offer cover read one small copy (`smallest(px × 2)`). A photo without copies keeps its single file: never a broken image. Photos uploaded before this day: admin → Settings → **Make photo sizes** reads each one back (needs `GET` in the R2 CORS policy), makes the copies and uploads them; the shop uses them from its next rebuild. **Samples**: an mp3 above ~160 kbps (bytes × 8 / duration) is decoded at 44.1 kHz and encoded again at 128 kbps CBR with lamejs 1.2.1 (LGPL, from jsDelivr with SRI, loaded only then). A 128 stays as it is (a second encode only loses quality); a file the browser cannot read, or no encoder, uploads as it is. ID3 tags are not kept (titles live in the database).
**Rule.** A file the shop shows is made at the size of the spot that shows it, at upload, in the admin, from one list of sizes in `packages/images`. A component image takes optional `srcSet` / `sizes`: fixed-size images default `sizes` to their own size, fluid ones get it from the page (the page knows its grid). Never point the shop at a copy the build has not seen.
**Where.** `packages/images/images.js`, `apps/admin/admin.js` (toWebp, uploadPhoto, uploadSizes, toSampleMp3, uploadFile, Settings → PhotoSizes), `apps/admin/build.js` + `index.html`, `supabase/functions/sign-upload`, `supabase/functions/purge-media`, `apps/storefront/data/products.js` (markSized), `apps/storefront/pages/shell.js` (IMAGE_SIZES, imageOf, smallImageUrl), `pdp.js`, `bag.js`, `trade.js`, `packages/ui/components.js` + `.d.ts` (srcSet/sizes on ProductCard, BagItem, OrderRow, Gallery, Player).
