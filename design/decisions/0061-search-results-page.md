# 0061 — Search: a results page that is a PLP; sold copies stay visible behind "Show sold out"

`2026-11-12` · accepted (Gio) · Figma: page `Search` (2214:5454), `header` boolean `search`, `filters` / `filters layer` → "Show sold out"

**Context.** The shop had no search. Gio: the search must load a results page, "a kind of PLP" with the filters; sold records must stay visible, with a "Show sold out" tick on by default in every filter column.
**Decision.** Header (Figma boolean `search`, on in the main): desktop = `input` type=search, 200 wide, before Account; mobile = the magnifier Button (as the hamburger) → `/search/`. Enter opens `/search/?q=…`: the PLP of the sale copies with no section tab, `search heading` ("N results for “q”" / "No results for “q”", body/large), on mobile the `search field` under the header, `search message` as the empty state (no results: hint + "Browse all records" → /sale/; no query: the hint only). Matching is client-side on a normalised text per card (artist and artist entities, title, track titles, label, catalogue number, genres, tags): every query word must start a word of the record, or the query without spaces/dashes appears in it. Sold copies are on the PLP and the search page; their Add buttons read "Sold out", disabled (struck through = unavailable, 0058). "Show sold out" (`filter` state=active, no count) is the first row of the filter column and of the mobile layer; unticked = `?sold=hide`; it is a view option, not a filter: not counted in "Filter (n)", Reset ticks it again.
**Rule.** A page that lists copies offers "Show sold out" (ticked) instead of dropping sold copies. A sold copy's Add button is disabled "Sold out"; it never adds to the bag.
**Where.** `packages/ui/components.js` (`Header` `search` / `searchHref`), `components.css`; `apps/storefront/pages/shell.js` (`SearchForm`), `pages/plp.js` (`search`, `searchTextOf`, `ShowSold`), `build.js` (`search/index.html`, sold in the PLP), `plp.css`, `scripts/site.js` (`initSearch`, filters, `syncAddButton`).
