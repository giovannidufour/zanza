# 0088 — Product card hover: the whole card takes surface/hover

`2026-11-15` · accepted (Gio: "tutte le card sul sito… ad hover… lo sfondo di tutta la card diventa leggermente più scuro… black A04… crea la variabile semantica se necessario") · Figma: page `PDP` → `product card` (2050:12869), new variant property `state` = default | hover; variable `color` → `surface/hover` (VariableID:2298:16442)

**Context.** Product cards (PLP, catalog, search, home Just in, PDP "More for sale" / "More for trade") had no hover state; only the cover and title links reacted (0040, underline in code).
**Decision.** On hover the whole card gets a background in the new semantic variable `surface/hover` = `black-a4` in both modes (frontend, backend), scopes frame/shape fill. A new variable instead of reusing `surface/subtle` (locked field, drop zone: a static state) or `action/floating/background/hover` (chromeless controls): same value today, different meaning, so they can diverge without touching the card. Figma: `product card` gets `state=hover` for both devices, fill bound to `surface/hover`; existing instances stay `state=default`. Code: `.zz-product-card:hover` under `@media (hover: hover)` (a tap on touch does not leave the card tinted), plus `[data-state="hover"]` for docs (0009). No transition (none designed).
**Rule.** A block that reacts as a whole on hover takes `surface/hover` as its background, never a raw alpha primitive. The card keeps its padding (none): the tint is the card box as it is, nothing moves. A sold-out cover (0086) goes back to colour and normal blending on the card hover, wherever the pointer is on the card (Gio, 2026-11-15), not only on the image; bag item and PDP gallery keep the image hover.
**Where.** `packages/ui/tokens.json` (`surface-hover`), `components.css` (`.zz-product-card`), `components.js` + `components.d.ts` (ProductCard `state`).
