# 0072 — Minimum order: records only, set in admin Shipping, the bag says what is missing and Checkout waits

`2026-11-13` · accepted (Gio: "Solo subtotale dischi") · Figma: Bag → `bag summary` variant `minimum` = reached | below + text `minimum note`, screens `Bag - desktop · below minimum` (2247:1721) / `Bag - mobile · below minimum` (2247:2132); BACKEND → Shipping → component `minimum order` (2247:3101)

**Context.** Gio wants a minimum order value, editable from the admin and reflected in the bag. Records are a few euros each and shipping is a fixed cost per parcel: tiny orders are not worth packing. The bag is static HTML plus `site.js`; create-checkout (hold + Stripe session) is not built yet.
**Decision.**
- The minimum counts the **subtotal of the records being bought**: available lines only (sold and reserved lines are already out of the order, 0064/0065), **shipping excluded** (Gio, 2026-11-13). Changing the country never changes whether the bag can check out.
- Stored as `min_order_cents` in the `shipping_settings` config (no migration): one admin page, one Save, and the save already rebuilds the shop. Empty / 0 = no minimum. Edited in the section "Minimum order" at the top of the admin page Shipping.
- One rule, `ZanzaShipping.minimumOrder(config, subtotal_cents)` in `packages/shipping/shipping.js`, for the bag and for create-checkout. The bag page carries the minimum in `data-min-order-cents`.
- Bag under the minimum (and with at least one available record): `minimum note` above Checkout, body/small, "Minimum order 20€. Add 3€ more to check out."; Checkout disabled, with `aria-describedby` on the note, so the disabled button is never unexplained. The note is a polite live region (heard when it appears or the amount changes); reaching the minimum announces "Minimum order reached. You can check out." The subtotal, shipping and total rows stay.
- Server: create-checkout re-checks after taking the holds (the subtotal of the copies it actually held, prices from the DB). Below the minimum → it releases the holds and returns `below_minimum` with the amount missing; no Stripe session. A copy that sold in the meantime can drop a bag under the minimum: the bag then shows the note again.
**Rule.** A threshold that blocks checkout is computed by the same shared function in the browser and on the server, says the number and what is missing in words next to the action, and the blocked action points to those words.
**Struck through (Gio, 2026-11-13: "la prima").** Below the minimum Checkout stays a disabled Button, label struck through, like `destination=not served` (0057). This bends 0058/0059 ("struck through = unavailable for good") for the bag's Checkout only: the note next to it says why and what is missing. Rejected: an active "(Add 3€) Browse records" button (0065 pattern).
**Where.** `packages/shipping/shipping.js` (`minimumOrder`, `validate`) · `apps/admin/admin.js`, `admin.css` (Shipping → Minimum order) · `packages/ui` BagSummary (`minimumNote`, `minimumNoteProps`) · `apps/storefront/pages/bag.js`, `scripts/site.js` (`renderMinimum`) · `_context/backend.md` (Checkout con hold).
